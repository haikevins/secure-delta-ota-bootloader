# Phase 9 — ESP32 UART Gateway

Status: **implemented; hardware validation command provided**

Phase 9 replaces the PC Python sender as the normal transport peer with a
classic ESP32 running ESP-IDF. The STM32 protocol and memory maps remain
unchanged.

## Architecture

```text
Phase-9 embedded STM32 candidate
             |
             v
      ESP32 stm32_cache
             |
     UART2 115200 8-N-1
             |
   COBS + 0x00 + CRC32
             |
             v
   STM32 USART1 PA9/PA10
             |
             v
   W25Q Incoming Artifact
             |
          INSTALL
             |
 backup -> install -> trial -> confirm
```

Phase 10 will replace the embedded seed with HTTPS download. Phase 11 will add
MQTT control/status. The `uart_ota` component itself does not know where the
artifact came from.

## ESP32 target and pins

Phase 9 targets the original ESP32/WROOM/DevKit class target:

```bash
idf.py set-target esp32
```

Defaults:

| Signal | ESP32 | STM32F103 |
|---|---:|---:|
| Gateway TX | GPIO17 | PA10 / USART1 RX |
| Gateway RX | GPIO16 | PA9 / USART1 TX |
| Ground | GND | GND |

UART0 remains the ESP-IDF console. UART2 is the STM32 link. Pins are
menuconfig options under `Secure Delta OTA Phase 9`.

Use 3.3 V logic. Do not drive PA9/PA10 simultaneously from a PC USB-UART while
the ESP32 gateway is connected.

## ESP-IDF APIs used

The implementation uses the normal ESP-IDF UART driver workflow:

- `uart_param_config()`
- `uart_set_pin()`
- `uart_driver_install()`
- `uart_write_bytes()`
- `uart_read_bytes()`

The cache uses the partition API:

- `esp_partition_find_first()`
- `esp_partition_read()`
- `esp_partition_write()`
- `esp_partition_erase_range()`

Protocol timeouts use monotonic `esp_timer_get_time()`.

The Phase-9 code is intended for ESP-IDF 5.4+ and current ESP-IDF 6.x on the
classic `esp32` target.

## ESP32 artifact cache

Partition `stm32_cache` is 192 KiB. The first 4 KiB is a header sector and the
artifact starts at offset `0x1000`.

The seed transaction is power-cut safe at publication level:

```text
erase artifact range
write artifact bytes
read back / CRC32
erase header sector
write CRC-protected header last
```

If ESP32 loses power before the header is committed, `ArtifactCache_Open()`
rejects the cache and the embedded Phase-9 seed is written again.

## Gateway protocol behavior

The gateway first sends QUERY and chooses one of these actions:

- target already at requested version + `IDLE` -> success;
- `IDLE` -> START;
- same `update_id` in `RECEIVING` -> RESUME from STM32-reported offset;
- foreign/stale transfer -> ABORT then START;
- same artifact already `ARTIFACT_READY` -> INSTALL;
- backup/install/trial/rollback in progress -> wait for final state.

DATA uses 256-byte chunks. Timeout is 1500 ms and retry count is five.

The STM32's persisted 4 KiB resume offset remains authoritative. The gateway
derives the sequence as `offset / 256`.

An INSTALL ACK may be lost because STM32 resets immediately after the response.
The gateway therefore treats the final application version/state as
authoritative and waits through the bootloader-only interval.

## Build

Activate ESP-IDF first, for example using the `export.sh` supplied by your
installed ESP-IDF, then:

```bash
make phase9-check
make phase9-gateway-build
```

The STM32 candidate embedded in the gateway is generated by:

```bash
make phase9-candidate
python3 scripts/phase9_prepare_gateway.py
```


## OpenOCD isolation when ESP-IDF is active

ESP-IDF `export.sh` prepends Espressif tools to `PATH` and may set
`OPENOCD_SCRIPTS`. That OpenOCD build is intended for ESP targets and must not
be used for the STM32 ST-Link stage.

`phase9_hw_test.py` therefore resolves a separate STM32 OpenOCD and starts it
with an explicit script directory:

```text
STM32_OPENOCD=/usr/bin/openocd
STM32_OPENOCD_SCRIPTS=/usr/share/openocd/scripts
```

The runner removes ESP-IDF's `OPENOCD_SCRIPTS`/`OPENOCD_COMMANDS` from the
STM32 OpenOCD subprocess. It auto-prefers `/usr/bin/openocd` and
`/usr/local/bin/openocd` before searching `PATH`, while skipping Espressif
`openocd-esp32` installations.

If auto-detection cannot find the STM32 installation, run:

```bash
STM32_OPENOCD=/usr/bin/openocd \
STM32_OPENOCD_SCRIPTS=/usr/share/openocd/scripts \
make phase9-hw-test ESP32_PORT=/dev/ttyUSB0
```

## Hardware test

First wire ESP32 UART2 to the STM32 as above and leave ST-Link connected to the
STM32.

Then:

```bash
make phase9-hw-test ESP32_PORT=/dev/ttyUSB0
```

The runner:

1. flashes the STM32 Phase-9 baseline application v1;
2. erases STM32 internal metadata;
3. flashes the ESP32 gateway;
4. gateway caches the embedded healthy v2 candidate;
5. gateway sends v2 through UART;
6. STM32 performs the Phase-8 backup/install/trial/confirm flow;
7. script waits for `P9_GATEWAY_HW_TEST=PASS`;
8. ST-Link dumps STM32 metadata and installed bytes;
9. installed bytes must match the gateway candidate exactly.

Expected final STM32 state:

```text
state=IDLE
active_version=2
pending_version=0
boot_attempts=0
copy_offset=0
last_error=0
```
