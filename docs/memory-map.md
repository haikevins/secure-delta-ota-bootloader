# Memory Map Specification

Status: **Frozen for Phase 0**

All addresses are inclusive unless stated otherwise.

## 1. STM32F103C8T6 internal Flash

Nominal size: 64 KiB, `0x08000000`–`0x0800FFFF`.

| Region | Start | End | Size | Purpose |
|---|---:|---:|---:|---|
| Bootloader | `0x08000000` | `0x08005FFF` | 24 KiB | Boot decision, validation, patch, install and rollback |
| Application | `0x08006000` | `0x0800FBFF` | 39 KiB | Active product application |
| Boot Metadata | `0x0800FC00` | `0x0800FFFF` | 1 KiB | Minimal boot-critical redundant records or pointer record |

Total: 24 + 39 + 1 = 64 KiB.

### Fixed symbols

```c
#define INTERNAL_FLASH_BASE          0x08000000UL
#define INTERNAL_FLASH_END           0x0800FFFFUL
#define BOOTLOADER_START_ADDRESS     0x08000000UL
#define BOOTLOADER_MAX_SIZE          (24UL * 1024UL)
#define APPLICATION_START_ADDRESS    0x08006000UL
#define APPLICATION_MAX_SIZE         (39UL * 1024UL)
#define BOOT_METADATA_ADDRESS        0x0800FC00UL
#define BOOT_METADATA_SIZE           (1UL * 1024UL)
```

### Application linker region

```ld
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08006000, LENGTH = 39K
    RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 20K
}
```

### Internal Flash safety rules

- Application image size must be `<= APPLICATION_MAX_SIZE`.
- No external artifact may specify a load address outside the application region.
- Bootloader erase/write routines reject every page intersecting the bootloader or metadata region unless the operation is the dedicated metadata API.
- The bootloader is linked with a hard maximum of 24 KiB and Phase 1 must fail the build if it exceeds this budget.
- The vector table of the application is located at `APPLICATION_START_ADDRESS`.

## 2. SRAM

Nominal SRAM: 20 KiB, `0x20000000`–`0x20004FFF`.

Phase 0 does not permanently reserve SRAM between bootloader and application. The bootloader must keep peak RAM small enough for streaming hash and patch operations.

Initial RAM targets:

| Component | Target |
|---|---:|
| UART encoded frame buffer | <= 320 bytes |
| UART decoded packet buffer | <= 320 bytes |
| Delta patch buffers | <= 2 KiB total |
| SHA-256 context and block | <= 256 bytes |
| SPI page buffer | <= 256 bytes |
| Remaining stack/headroom | >= 8 KiB |

## 3. W25Q32 external SPI NOR Flash

Nominal size: 4 MiB, `0x000000`–`0x3FFFFF`.

Erase sector size: 4 KiB. Program page size: 256 bytes.

| Region | Start | End | Allocated size | Purpose |
|---|---:|---:|---:|---|
| Metadata A/B | `0x000000` | `0x001FFF` | 8 KiB | Two 4 KiB metadata sectors |
| Incoming Artifact | `0x002000` | `0x021FFF` | 128 KiB | Complete full/delta secure container |
| Reconstructed Image | `0x022000` | `0x041FFF` | 128 KiB | Target image generated by full extraction or delta patch |
| Backup Image | `0x042000` | `0x061FFF` | 128 KiB | Verified copy of active internal application |
| Update Logs | `0x062000` | `0x071FFF` | 64 KiB | Bounded diagnostic records |
| Reserved | `0x072000` | `0x3FFFFF` | Remaining | Future use |

### Fixed symbols

```c
#define EXT_FLASH_SIZE                0x400000UL
#define EXT_FLASH_SECTOR_SIZE         0x1000UL
#define EXT_FLASH_PAGE_SIZE           0x0100UL

#define EXT_METADATA_A_ADDRESS        0x000000UL
#define EXT_METADATA_B_ADDRESS        0x001000UL

#define EXT_INCOMING_ADDRESS          0x002000UL
#define EXT_INCOMING_SIZE             0x020000UL

#define EXT_RECONSTRUCTED_ADDRESS     0x022000UL
#define EXT_RECONSTRUCTED_SIZE        0x020000UL

#define EXT_BACKUP_ADDRESS            0x042000UL
#define EXT_BACKUP_SIZE               0x020000UL

#define EXT_LOG_ADDRESS               0x062000UL
#define EXT_LOG_SIZE                  0x010000UL
```

## 4. Partition invariants

- All external partitions begin and end on a 4 KiB erase-sector boundary.
- Incoming, reconstructed and backup regions each exceed the maximum internal application size.
- Patching reads the active internal application and incoming patch while writing only to reconstructed storage.
- Backup must verify before internal application erase begins.
- Incoming data is not considered valid until artifact length and CRC32 match the START metadata.
- Reconstructed target is not considered valid until target image SHA-256 matches the signed header.
- Backup is erased only after application confirmation and retention policy completion.

## 5. Address validation requirements

Every storage API must validate:

```text
address >= partition_start
length <= partition_size
address + length does not overflow
address + length <= partition_end + 1
```

No caller may bypass these checks by using the raw driver directly outside storage modules.
